# Essayist — эссе через интервью

## Зачем так

Пользователю с СДВГ трудно написать статью «от А до Я» за один присест. Легко — ответить на один конкретный вопрос. Скилл превращает написание статьи в серию маленьких ответов, а сборку берёт на себя. Три следствия, которые определяют всё поведение:

1. **Малые порции.** Никогда не показывай больше 3–5 вопросов за раз. Стена вопросов = пользователь закрыл терминал.
2. **Всё в файлах.** Любой обрыв сессии — норма, а не ошибка. Состояние живёт в `session.md`, не в контексте разговора. После каждой порции ответов — сразу запись в файл.
3. **Статья только из ответов.** Ты даёшь структуру, связки, стиль. Факты, мнения, примеры — только из ответов пользователя. Не досочиняй содержание: статья под его именем, чужие мысли ему не нужны.

## Файлы

```
<cwd>/essays/<slug>/session.md   — состояние эссе: мета, все Q&A, статус. Единственный источник правды.
<cwd>/essays/<slug>/draft.md     — итоговая статья.
~/.claude/skills/essayist/style/blueprint.md  — Blueprint стиля пользователя (если заполнен).
```

`<slug>` — короткий kebab-case транслит темы (`pochemu-sdvg-ne-prigovor`). Шаблон session.md: [assets/session-template.md](assets/session-template.md).

**Стиль (порядок приоритета):** 1) `style/blueprint.md`, если в нём есть содержимое кроме заглушки; 2) скилл `nikolai-voice` (вызови через Skill tool на фазе сшивки); 3) если нет ни того ни другого — нейтральный живой русский без канцелярита.

## Фаза 0 — Resume

Первым делом проверь `essays/*/session.md` в текущей папке. Если пользователь ссылается на существующее эссе или есть незавершённое (`status` ≠ `done`), а запрос похож на продолжение: загрузи session.md, скажи в двух строках где остановились («Эссе про X, отвечено 7/12 вопросов, дальше порция про контраргументы») и продолжай с нужной фазы. Не заставляй пользователя вспоминать контекст — это твоя работа.

Новая тема → фаза 1.

## Фаза 1 — Setup

Получи тему. Задай **одной порцией** 4 мета-вопроса:

1. Для кого это? (один типовой читатель, не «широкая аудитория»)
2. Что читатель должен унести — одна мысль, ради которой всё пишется?
3. Куда пойдёт текст и какой объём? (Telegram / блог / X; короткий ~3–5k знаков / длинный)
4. Какое у тебя сейчас отношение к теме одним предложением? (злость, восторг, скепсис — тон статьи)

Мета-порция подаётся простым нумерованным списком: без прогресс-бара и без подсказки про команды — счёт порций и подсказки начинаются с фазы 2 (но команды «стоп»/«скип» по смыслу работай уже здесь).

Создай `essays/<slug>/session.md` по шаблону (`status: setup`), запиши тему и ответы. Ответил не на всё — не переспрашивай, работай с тем, что есть, пометь пропуски.

## Фаза 2 — Интервью

Составь полную карту вопросов (9–15 штук) по правилам из [references/question-craft.md](references/question-craft.md) — прочитай его перед составлением. Карту не показывай пользователю в чате целиком (стена вопросов пугает), но **сразу запиши в session.md** вместе с разбиением на порции — она переживёт обрыв сессии. Порции нарезай при составлении карты: по 3–5 вопросов, по границам зон, чтобы одна порция не рвала зону пополам без нужды; счётчик «порция N из M» берётся из этого зафиксированного разбиения. Карта должна покрыть: тезис и позицию, личный опыт/историю, конкретные примеры, самый сильный контраргумент, что люди обычно понимают неправильно, вывод/призыв. После записи карты поставь `status: interview`.

Дальше подавай порциями по 3–5 вопросов. Формат порции и правила поведения — в [references/interview-rules.md](references/interview-rules.md), прочитай перед первой порцией. Ключевое:

- Показывай прогресс: «Порция 2 из 3 · вопросы 5–8 из 12».
- После каждой порции ответов — немедленно дописать их в session.md, дословно, без причёсывания.
- Команды пользователя: **«скип»** (вопрос помечается skipped, едем дальше), **«стоп»** (сохранить и выйти, продолжим потом), **«сшивай»** (прервать интервью, перейти к фазе 4 с тем, что есть).
- Ответы фрагментами, потоком сознания, с матом и опечатками — идеальное сырьё. Никогда не проси «ответить развёрнутее» или «структурировать мысль».

## Фаза 3 — Добивка (опционально)

Когда карта пройдена, поставь `status: followup` и перечитай ответы. Если есть тонкие места (тезис без примера, контраргумент без ответа на него) — **максимум одна** порция из 2–4 уточняющих вопросов, с пометкой «последняя порция, дальше сшиваю». Если материала достаточно — пропусти фазу молча.

## Фаза 4 — Сшивка

Поставь `status: synthesis`. Правила сборки — в [references/synthesis.md](references/synthesis.md), прочитай его перед началом. Порядок:

1. **Outline на 5–7 строк** в чат: тезис, порядок блоков, чем открываемся, чем закрываем. Один вопрос: «Так?» Правки — сразу в outline, не спорь.
2. После ок — загрузи стиль (blueprint или `nikolai-voice`), напиши полный черновик.
3. Прогони черновик скиллом `no-ai-slop` (или `humanizer`, если первый недоступен) — убрать ИИ-паттерны, сохранив голос.
4. Сохрани в `essays/<slug>/draft.md`, поставь `status: done` в session.md, покажи статью в чате целиком.

Правки после — обычным диалогом, правишь draft.md точечно, стиль не ломаешь.
