# Essayist — тексты через интервью

## Зачем так

Пользователю с СДВГ трудно написать текст «от А до Я» за один присест. Легко — ответить на один конкретный вопрос. Скилл превращает написание в серию маленьких ответов, а сборку берёт на себя. Три следствия, которые определяют всё поведение:

1. **Малые порции.** Никогда не показывай больше 3–5 вопросов за раз. Стена вопросов = пользователь закрыл терминал.
2. **Всё в файлах.** Любой обрыв сессии — норма, а не ошибка. Состояние живёт в `session.md`, не в контексте разговора. После каждой порции ответов — сразу запись в файл.
3. **Текст только из ответов.** Ты даёшь структуру, связки, стиль. Факты, мнения, примеры — только из ответов пользователя. Не досочиняй содержание: текст под его именем, чужие мысли ему не нужны.

## Файлы

Все работы живут в **одном месте**, независимо от того, из какой папки запущен скилл:

```
~/code_projects/esseist_framework/essays/           — база (далее <base>)
<base>/_ideas.md                                    — копилка тем
<base>/<slug>/session.md                            — состояние: мета, все Q&A, статус
<base>/<slug>/draft.md                              — готовый текст
~/.claude/skills/essayist/style/blueprint.md        — Blueprint стиля (если заполнен)
```

`<slug>` — короткий kebab-case транслит темы. Шаблон session.md: [assets/session-template.md](assets/session-template.md).

**Стиль (порядок приоритета):** 1) `style/blueprint.md`, если в нём есть содержимое кроме заглушки; 2) скилл `nikolai-voice` (вызови через Skill tool на фазе сшивки — у него есть режимы под пост/сценарий/эссе); 3) нейтральный живой русский без канцелярита.

## Форматы

Формат определи из запроса, не спрашивая, когда он очевиден: «сценарий», «видео», «ютуб» → `youtube-script`; «пост», «в телегу» → `tg-post`; «тред», «в X/твиттер» → `x-thread`; «эссе», «статья», «в блог» и всё остальное длинное → `essay`. Неочевидно — один вопрос одной строкой.

- **essay** — базовый формат, весь этот файл описывает его. Остальные форматы — дельты поверх базы:
- **youtube-script** → прочитай [references/formats/youtube-script.md](references/formats/youtube-script.md)
- **tg-post** → прочитай [references/formats/tg-post.md](references/formats/tg-post.md)
- **x-thread** → прочитай [references/formats/x-thread.md](references/formats/x-thread.md)

Формат пишется в yaml session.md (`format:`) при создании.

## Копилка идей

СДВГ-паттерн: тема пришла в голову — и потерялась. Команда **«в копилку»** (в любой момент, даже посреди интервью): дописать строку в `<base>/_ideas.md`, подтвердить одной строкой, вернуться к текущему делу.

Формат строки: `- YYYY-MM-DD [формат] тема — источник: путь`. `[формат]` (эссе/видео/TG) и источник опциональны. Источник — заметка или папка в волтах пользователя, алиасы путей (RC, CC) расшифрованы в `style/sources-map.md` — личный файл, в репо его нет; нет файла или алиаса в нём — запиши источник как дал пользователь, не гадай путь. Темы в файле сгруппированы пустыми строками по кластерам — группировку сохраняй. Взятую в работу тему из копилки удаляй.

**Тема с источником** — это полуфабрикат: перед интервью прочитай [references/sources.md](references/sources.md) и работай по нему (читаешь источник, извлекаешь тезисы, интервью сжимается до вопросов на дыры).

## Дашборд «что у нас»

Команды «что у нас», «что по текстам», «давай что-нибудь напишем» → покажи компактную сводку:

1. **Незавершённые** (`status` ≠ done): по строке — формат, тема, где остановились («интервью 7/12»).
2. **Копилка** по кластерам: название кластера + число тем + 1–2 самые сочные (приоритет темам с жирным источником — готовым черновиком сценария или развёрнутой заметкой).
3. Одна рекомендация: «предлагаю взять X — незакончено/жирный источник/быстрый формат».

Не вываливай все 60 тем списком — это стена. Кластеры + счётчики + выбор.

## Фаза 0 — Resume

Первым делом проверь `<base>/*/session.md`. Если пользователь ссылается на существующую работу или есть незавершённая (`status` ≠ `done`), а запрос похож на продолжение: загрузи session.md, скажи в двух строках где остановились («Эссе про X, отвечено 7/12, дальше порция про контраргументы») и продолжай с нужной фазы. Не заставляй пользователя вспоминать контекст — это твоя работа.

Новая тема → фаза 1 (у темы есть источник → сначала [references/sources.md](references/sources.md)).

## Фаза 1 — Setup

Получи тему. Задай **одной порцией** 4 мета-вопроса (у форматов свои наборы — см. файл формата; для эссе):

1. Для кого это? (один типовой читатель, не «широкая аудитория»)
2. Что читатель должен унести — одна мысль, ради которой всё пишется?
3. Куда пойдёт текст и какой объём? (блог / Telegram; короткий ~3–5k знаков / длинный)
4. Какое у тебя сейчас отношение к теме одним предложением? (злость, восторг, скепсис — тон текста)

Мета-порция подаётся простым нумерованным списком: без прогресс-бара и без подсказки про команды — счёт порций и подсказки начинаются с фазы 2 (но команды «стоп»/«скип» по смыслу работай уже здесь).

Создай `<base>/<slug>/session.md` по шаблону (`status: setup`, `format:`), запиши тему и ответы. Ответил не на всё — не переспрашивай, работай с тем, что есть, пометь пропуски.

## Фаза 2 — Интервью

Составь полную карту вопросов (для эссе 9–15 штук; у форматов свои размеры) по правилам из [references/question-craft.md](references/question-craft.md) — прочитай его перед составлением. Карту не показывай пользователю в чате целиком (стена вопросов пугает), но **сразу запиши в session.md** вместе с разбиением на порции — она переживёт обрыв сессии. Порции нарезай при составлении карты: по 3–5 вопросов, по границам зон, чтобы одна порция не рвала зону пополам без нужды; счётчик «порция N из M» берётся из этого зафиксированного разбиения. Карта должна покрыть: тезис и позицию, личный опыт/историю, конкретные примеры, самый сильный контраргумент, что люди обычно понимают неправильно, вывод/призыв. После записи карты поставь `status: interview`.

Дальше подавай порциями по 3–5 вопросов. Формат порции и правила поведения — в [references/interview-rules.md](references/interview-rules.md), прочитай перед первой порцией. Ключевое:

- Показывай прогресс: «Порция 2 из 3 · вопросы 5–8 из 12».
- После каждой порции ответов — немедленно дописать их в session.md, дословно, без причёсывания.
- Команды пользователя: **«скип»** (вопрос помечается skipped, едем дальше), **«стоп»** (сохранить и выйти, продолжим потом), **«сшивай»** (прервать интервью, перейти к фазе 4 с тем, что есть), **«в копилку …»** (записать тему в `_ideas.md`, продолжить).
- Ответы фрагментами, потоком сознания, с матом и опечатками — идеальное сырьё. Никогда не проси «ответить развёрнутее» или «структурировать мысль».

## Фаза 3 — Добивка (опционально)

Когда карта пройдена, поставь `status: followup` и перечитай ответы. Если есть тонкие места (тезис без примера, контраргумент без ответа на него) — **максимум одна** порция из 2–4 уточняющих вопросов, с пометкой «последняя порция, дальше сшиваю». Если материала достаточно — пропусти фазу молча.

## Фаза 4 — Сшивка

Поставь `status: synthesis`. Правила сборки — в [references/synthesis.md](references/synthesis.md), прочитай его перед началом. Порядок:

1. **Outline на 5–7 строк** в чат: тезис, порядок блоков, чем открываемся, чем закрываем. Один вопрос: «Так?» Правки — сразу в outline, не спорь. (У коротких форматов outline пропускается — см. файл формата.)
2. После ок — загрузи стиль (blueprint или `nikolai-voice`), напиши полный черновик.
3. Прогони черновик скиллом `no-ai-slop` (или `humanizer`, если первый недоступен) — убрать ИИ-паттерны, сохранив голос.
4. Проверь объём (`wc -m`) против меты — правило в synthesis.md.
5. Сохрани в `<base>/<slug>/draft.md`, поставь `status: done` в session.md, покажи текст в чате целиком.

Правки после — обычным диалогом, правишь draft.md точечно, стиль не ломаешь.

## Фаза 5 — Публикация (только по команде)

Команда **«публикуй»** для готового эссе → прочитай [references/publish.md](references/publish.md) и следуй ему (общий порядок + конфиг твоей площадки, опционально EN-перевод). Для tg-post и x-thread публикации нет — текст отдаётся в чат для копипаста. Никогда не публикуй без явной команды.
